📖 Plain-English Jargon Buster ​

Security documentation loves throwing around heavy words like canonicalization, tautology, idempotent, and deserialization. You don't need a computer science degree to understand what is happening on the wire. Use this dictionary anytime a term feels fuzzy—every entry explains what the word actually means in plain English and gives you an everyday analogy.

Stage 3 · Databases & Backend

String Concatenation

In Plain English: Gluing pieces of text together end-to-end—like pasting a user’s search word directly into the middle of a database command.

💡 Think of it like: Like writing a blank line on an official contract where someone can write extra legal clauses instead of just their name.

Appears in:Mental Model & First Contact →
Stage 3 · Databases & Backend

Parameterized Query (Prepared Statement)

In Plain English: A safe way to run database commands where the command structure is locked in first, and user input is sent separately in a sealed box.

💡 Think of it like: Like a shipping label with a pre-printed barcode slot: no matter what you write inside the box, it cannot change the delivery instructions.

Appears in:Mental Model & First Contact → UNION Attacks →
Stage 3 · Databases & Backend

Tokenizer (Lexer)

In Plain English: The very first step inside a database or browser that chops a raw line of text into individual words, punctuation marks, and strings.

💡 Think of it like: Like your eyes spotting spaces and quotation marks on a page before your brain even thinks about what the sentence means.

Appears in:Mental Model & First Contact → WAF Bypass & XML Encoding →
Stage 3 · Databases & Backend

Always-True Condition (Tautology)

In Plain English: A simple math or text comparison like `1=1` that is always true, used to trick a database filter into saying "yes" to every row.

💡 Think of it like: Like telling a bouncer: "Let me in if my name is on the list OR if 2+2 equals 4."

Appears in:Mental Model & First Contact →
Stage 3 · Databases & Backend

UNION Operator

In Plain English: A SQL keyword that staples the results of a second query directly onto the bottom of the original query’s results.

💡 Think of it like: Like sneaking an extra page of names onto the bottom of an official guest list printout—as long as your page has the exact same columns.

Appears in:UNION Attacks → Database Fingerprinting →
Stage 3 · Databases & Backend

System Catalog (information_schema)

In Plain English: A built-in master directory inside the database that lists the names of every table and column stored on the server.

💡 Think of it like: Like the "Directory" sign in a shopping mall lobby that tells you the exact floor and room number of every store.

Appears in:Database Fingerprinting →
Stage 3 · Databases & Backend

Yes/No Signal (Oracle)

In Plain English: Any tiny clue in a server’s response—like a missing "Welcome" banner, an error status, or a 5-second pause—that tells you whether a guess was true or false.

💡 Think of it like: Playing the game "20 Questions" with someone who only nods or blinks to answer.

Appears in:Blind SQL Injection → Authentication → NoSQL Injection →
Stage 3 · Databases & Backend

Out-of-Band (OAST)

In Plain English: Tricking a quiet server into making a phone call (DNS or HTTP lookup) out to a server you control when the normal webpage shows nothing.

💡 Think of it like: Slipping a note under a locked door that says "If you can read this, call my cell phone number."

Appears in:Blind SQL Injection → OS Command Injection → XXE Injection → Server-Side Request Forgery (SSRF) →
Stage 3 · Databases & Backend

XML / HTML Character Entity

In Plain English: A coded nickname for a character (like `&#x27;` for a single quote) that an XML reader translates back into the real character before passing it on.

💡 Think of it like: Spelling a forbidden word in Morse code so the security guard at the front gate doesn’t recognize it, knowing the clerk inside will translate it back.

Appears in:WAF Bypass & XML Encoding → XXE Injection →
Stage 3 · Databases & Backend

WAF (Web Application Firewall)

In Plain English: A security filter sitting in front of a website that inspects incoming traffic and blocks requests that look suspicious.

💡 Think of it like: An airport luggage scanner that checks bags before they reach the plane—if it looks at the bag differently than the destination crew, things slip through.

Appears in:WAF Bypass & XML Encoding → Cross-Site Scripting (XSS) →
Stage 1 · Recon

Path Normalization (Canonicalization)

In Plain English: The process where an operating system simplifies a messy file path like `/images/../../etc/passwd` down to its real final destination `/etc/passwd`.

💡 Think of it like: Following directions that say "Walk two floors up, then four floors down"—what matters is the floor you actually end up on.

Appears in:Path Traversal → Web Cache Deception →
Stage 1 · Recon

URL Encoding (Percent-Encoding)

In Plain English: Replacing special characters in a web address with `%` followed by their hex code (like `%2f` for `/`) so they travel safely inside a URL.

💡 Think of it like: Packing fragile items in bubble wrap for shipping; the problem starts when a security check inspects the bubble wrap instead of unwrapping it first.

Appears in:Path Traversal → Essential Skills → WAF Bypass & XML Encoding →
Stage 1 · Recon

Debug Artifacts & Source Maps

In Plain English: Leftover developer files (like `.bak`, `.git`, or `.js.map`) accidentally left on a live website that reveal how the code works behind the scenes.

💡 Think of it like: Leaving the architectural blueprints and spare key notes taped to the front window after construction finishes.

Appears in:Information Disclosure → Essential Skills →
Stage 2 · Logins & Logic

Account Enumeration

In Plain English: Figuring out which usernames or emails actually exist on a website by watching how the login or password-reset page responds.

💡 Think of it like: Dialing extensions in an office building to see which ones ring vs. which ones play "That extension does not exist."

Appears in:Authentication →
Stage 2 · Logins & Logic

Session Cookie / Token

In Plain English: A digital wristband the server gives your browser after you log in, so you don’t have to type your password on every single click.

💡 Think of it like: A VIP concert wristband: once you have it on your wrist, the guards inside don’t check your ID anymore—they just look at the wristband.

Appears in:Authentication → CSRF → Cross-Site Scripting (XSS) →
Stage 2 · Logins & Logic

IDOR (Insecure Direct Object Reference)

In Plain English: When a website lets you view or edit someone else’s private data simply by changing an ID number in the URL or request (like `id=102` to `id=103`).

💡 Think of it like: A hotel where your room key opens any door as long as you tell the elevator which room number you want to visit.

Appears in:Access Control → API Testing →
Stage 2 · Logins & Logic

Horizontal vs. Vertical Access

In Plain English: Horizontal means accessing another regular user’s account; Vertical means jumping from a regular user up to an Administrator.

💡 Think of it like: Horizontal is peeking into a coworker’s desk drawer; Vertical is walking into the CEO’s office and signing company checks.

Appears in:Access Control →
Stage 2 · Logins & Logic

Workflow / Step-Skipping Flaw

In Plain English: When a website assumes you will always click Step 1 → Step 2 → Step 3 in order, and forgets to check if you jumped straight from Step 1 to Step 3.

💡 Think of it like: Walking past the cash register straight to the "Pickup Counter" because the pickup clerk assumes anyone standing there already paid.

Appears in:Business Logic → Authentication →
Stage 2 · Logins & Logic

OAuth & redirect_uri

In Plain English: When you click "Sign in with Google/GitHub," `redirect_uri` is the return address where the login service sends your secret access ticket.

💡 Think of it like: Telling the post office where to forward your passport—if an attacker can change that forwarding address, your passport goes to their mailbox.

Appears in:OAuth Authentication →
Stage 2 · Logins & Logic

JWT (JSON Web Token) & Signature

In Plain English: A self-contained ID card stored in your browser. The signature at the end is a cryptographic wax seal proving nobody edited the text inside.

💡 Think of it like: A printed backstage pass with a hologram seal—if the guard forgets to check the hologram, anyone with a printer can write "ADMIN" on a card.

Appears in:JWT Attacks →
Stage 3 · Databases & Backend

NoSQL Query Operator ($ne, $regex)

In Plain English: Special JSON keys starting with `$` in databases like MongoDB that mean "not equal to" or "matches pattern" instead of plain text.

💡 Think of it like: Instead of handing a guard a password, handing them an official rulebook card that says "Accept anything that is NOT blank."

Appears in:NoSQL Injection →
Stage 3 · Databases & Backend

Shell Separator (;, |, &&, $())

In Plain English: Punctuation marks in a system terminal that mean "finish this command and immediately run a second command right after it."

💡 Think of it like: Adding "...and also open the safe" onto the end of a voice command to a smart speaker.

Appears in:OS Command Injection →
Stage 3 · Databases & Backend

SSRF & Internal Loopback (127.0.0.1)

In Plain English: Tricking a public web server into fetching a URL that points to its own private internal network (`localhost` or `169.254.169.254`) that outsiders cannot reach directly.

💡 Think of it like: Calling a receptionist inside a high-security building and asking them to read aloud a document pinned to the breakroom wall behind them.

Appears in:Server-Side Request Forgery (SSRF) →
Stage 3 · Databases & Backend

XML External Entity (SYSTEM / file://)

In Plain English: A feature in XML files that tells the parser "fetch the contents of this file on the server’s hard drive and paste it right here."

💡 Think of it like: A mail-merge placeholder in a Word document that automatically pulls in a secret file from the computer printing the letter.

Appears in:XXE Injection →
Stage 4 · Browser Bugs

XSS (Cross-Site Scripting) & Context

In Plain English: When an app takes untrusted text and puts it into a webpage in a way that makes the victim’s browser run it as JavaScript code.

💡 Think of it like: Writing stage directions on a teleprompter that the news anchor accidentally reads and acts out live on air.

Appears in:Cross-Site Scripting (XSS) → DOM-Based Vulnerabilities →
Stage 4 · Browser Bugs

CSP (Content Security Policy)

In Plain English: A browser rule sent by the server that restricts where JavaScript can be loaded from and whether inline scripts are allowed to run.

💡 Think of it like: A strict guest list for code: even if someone sneaks a script tag onto the page, the browser checks the list before running it.

Appears in:Cross-Site Scripting (XSS) →
Stage 4 · Browser Bugs

CSRF & SameSite Cookies

In Plain English: CSRF is when another website tricks your browser into sending a request to a site you’re logged into; `SameSite` tells the browser whether to attach your login cookie on cross-site requests.

💡 Think of it like: Someone forging a letter in your name while you’re asleep because your mail carrier automatically stamps your official seal on every envelope leaving your house.

Appears in:CSRF →
Stage 4 · Browser Bugs

DOM Source & Sink

In Plain English: A "Source" is where untrusted text enters browser JavaScript (like the URL bar); a "Sink" is a dangerous function (like `innerHTML`) that executes or renders it.

💡 Think of it like: A Source is an unlocked window where a package comes in; a Sink is the conveyor belt that feeds it straight into the factory engine.

Appears in:DOM-Based Vulnerabilities → Cross-Site Scripting (XSS) → Prototype Pollution →
Stage 4 · Browser Bugs

Transparent Iframe Overlay (Clickjacking)

In Plain English: Stacking an invisible, real website inside an `<iframe>` right on top of a fake button so when you click the fake button, you actually click the real site.

💡 Think of it like: Laying a sheet of invisible carbon paper over a prize-entry form so your signature lands on a bank check underneath.

Appears in:Clickjacking →
Stage 4 · Browser Bugs

Same-Origin Policy & CORS

In Plain English: Browsers normally forbid Website A from reading responses from Website B. CORS headers are permission slips where Website B says "I trust Website A to read my data."

💡 Think of it like: A bank refusing to read your balance over the phone unless the caller ID matches a pre-approved list of trusted partners.

Appears in:CORS →
Stage 4 · Browser Bugs

WebSocket Handshake

In Plain English: The single initial HTTP request that upgrades a normal webpage connection into a permanent, two-way live chat pipe between browser and server.

💡 Think of it like: Checking someone’s badge once when they open a direct walkie-talkie channel, and then trusting every message sent over that channel afterward.

Appears in:WebSockets →
Stage 5 · APIs, Files & AI

MIME Type & File Polyglot

In Plain English: A MIME type is a label like `image/jpeg` claiming what a file is; a polyglot is a file crafted to look like a valid image on the outside while containing executable code inside.

💡 Think of it like: Hiding a working hollow compartment inside a real hardcover book that passes an X-ray check as a book.

Appears in:File Upload →
Stage 5 · APIs, Files & AI

Mass Assignment (Auto-Binding)

In Plain English: When an API automatically copies every field from a user’s JSON request directly into a database user record—including hidden fields like `"isAdmin": true`.

💡 Think of it like: A self-checkout kiosk that lets customers scan their own "Employee 100% Discount" barcode if they bring one from home.

Appears in:API Testing → GraphQL →
Stage 5 · APIs, Files & AI

GraphQL Introspection

In Plain English: A built-in GraphQL query (`__schema`) that asks the API to print out its entire blueprint of queries, mutations, and hidden fields.

💡 Think of it like: Asking a restaurant waiter not just for the public menu, but for the kitchen’s complete recipe book and secret staff menu.

Appears in:GraphQL →
Stage 5 · APIs, Files & AI

Race Window (TOCTOU)

In Plain English: The tiny split-second gap between when a server checks a rule ("Do you have a coupon left?") and when it updates the database ("Mark coupon used").

💡 Think of it like: Swiping the same gift card at five cash registers at the exact same millisecond before the balance update finishes saving.

Appears in:Race Conditions → File Upload →
Stage 5 · APIs, Files & AI

Prompt Injection & Excessive Agency

In Plain English: Tricking an AI assistant into ignoring its developer instructions, especially dangerous when the AI has "agency" (tools to read emails, query databases, or delete accounts).

💡 Think of it like: Hiring a helpful intern, giving them the master keys to the office, and letting strangers send them emails with new instructions.

Appears in:Web LLM Attacks →
Stage 6 · Deep Internals

HTTP Desync (CL.TE / TE.CL)

In Plain English: When a front-end proxy and a back-end server disagree on where one HTTP request ends and the next one begins, letting an attacker sneak a hidden request inside.

💡 Think of it like: Two mail sorters counting envelopes differently—one counts by weight, the other by sticker—so a hidden letter gets stapled onto the next stranger’s mail.

Appears in:HTTP Request Smuggling →
Stage 6 · Deep Internals

Cache Key vs. Unkeyed Input

In Plain English: A web cache uses the "Cache Key" (usually the URL) to decide if two users want the same page. An "Unkeyed Input" is an extra header that changes the page content without changing the label on the saved copy.

💡 Think of it like: Writing "Drinking Water" on a shared office pitcher (the Cache Key) after slipping hot sauce into it via an uninspected side spout (Unkeyed Input).

Appears in:Web Cache Poisoning → Web Cache Deception → HTTP Host Header Attacks →
Stage 6 · Deep Internals

Deserialization & Gadget Chain

In Plain English: Deserialization turns saved bytes back into live code objects. A "gadget chain" links existing helper methods in the app together so unpacking the object automatically triggers a command.

💡 Think of it like: Building a Rube Goldberg machine out of ordinary office supplies already sitting on the server’s desk, triggered the moment a package is opened.

Appears in:Insecure Deserialization →
Stage 6 · Deep Internals

JavaScript Prototype (__proto__)

In Plain English: The shared fallback template that every JavaScript object inherits from. Polluting it adds a property to every single object in the app at once.

💡 Think of it like: Slipping a new rule into the master city building code so every house in town suddenly treats the back door as unlocked by default.

Appears in:Prototype Pollution →
Stage 6 · Deep Internals

Template Engine & SSTI

In Plain English: A tool (like Jinja2 or Twig) that fills placeholders like `{{user.name}}` into HTML. SSTI happens when user input is placed into the template blueprint itself instead of passed as data.

💡 Think of it like: Allowing a customer to edit the formulas inside the store’s Excel spreadsheet instead of just typing a number into a cell.

Appears in:Server-Side Template Injection →
Stage 6 · Deep Internals

HTTP Host Header

In Plain English: A line in every browser request telling the web server which domain name you typed—often blindly trusted by apps when generating password-reset links.

💡 Think of it like: Writing your own return address on an envelope and having the bank mail the victim’s replacement credit card to that address.

Appears in:HTTP Host Header Attacks →
